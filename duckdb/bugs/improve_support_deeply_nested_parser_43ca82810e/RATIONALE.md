# Rationale

Undoes the part of the fix that let `CatalogReservedSchema{TypeName,Identifier,Table}` take more than one schema
component (`ReservedSchemaQualification+` -> single `ReservedSchemaQualification`). Dotted names with a catalog plus a
nested schema path then no longer parse.

Hunks (all under src/src/):
- parser/peg/grammar/statements/common.gram: `CatalogReservedSchemaTypeName` (fix hunk @@ -164).
- parser/peg/grammar/statements/create_table.gram: `CatalogReservedSchemaIdentifier` (fix hunk @@ -980).
- parser/peg/grammar/statements/select.gram: `CatalogReservedSchemaTable` (fix hunk @@ -1761).
- include/duckdb/parser/peg/inlined_grammar.hpp, inlined_grammar.gram: regenerated with scripts/parser/inline_grammar.py
  (fix's generated byte-array hunks).
- parser/peg/transformer/transform_common.cpp / transform_select.cpp and include/.../peg_transformer.hpp:
  the three Transform* functions take a single `Identifier` schema instead of `vector<Identifier>`.
- parser/peg/transformer/transform_generated_trampoline.cpp: the three Initialize/Finalize trampolines hand-edited
  (PyYAML missing, generator could not run) to the non-repeat form.

Not reverted: the function-name, table-function and column-reference hunks (`*`, `NestedSchemaTableColumnName`), so the
oracle units that depend only on those still pass (see below).
