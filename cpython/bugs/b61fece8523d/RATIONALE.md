# Rationale

Fix: GH-125868, STORE_ATTR_WITH_HINT stored into an entry whose value was NULL
(and notified ADDED), instead of deopting.

Changed `Python/bytecodes.c` (`_STORE_ATTR_WITH_HINT`), with `Python/generated_cases.c.h`
and `Python/executor_cases.c.h` regenerated by the tier1/tier2 generators
(`optimizer_cases.c.h` came out unchanged):

1. Removed the `old_value == NULL` deopt; restored
   `event = old_value == NULL ? PyDict_EVENT_ADDED : PyDict_EVENT_MODIFIED`
   passed to `_PyDict_NotifyEvent`. This reverses the fix's bytecodes.c /
   generated_cases.c.h / executor_cases.c.h hunks (the NULL check and the
   always-MODIFIED event).
2. The key-kind check `dk_kind != DICT_KEYS_UNICODE` became
   `!DK_IS_UNICODE(...)`, which is the pre-fix form (`dk_kind != DICT_KEYS_GENERAL`).
   v3.15.2 additionally deopts on split-keys dicts, which hides the
   case: the oracle's dict is split (kind 2) with a NULL-valued entry for 'b'.
   Reverting it restores the older acceptance of split/unicode keys, so the bug
   is reachable again. This is the same defect (a hinted store into an entry
   that is not a live value) covered by a second path.

The `Lib/dis.py` hunk of the fix is unrelated to the oracle and was not reverted.

Oracle: `test.test_opcache.TestInstanceDict.test_125868` fails with
`AssertionError: 'value' != 0` (the store goes to the NULL slot, the lookup
still finds the old 'value'). The other 82 cases pass.
