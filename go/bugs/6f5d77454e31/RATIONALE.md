# Rationale

Fix (CL 568258): in copyelim's first all-values loop, rewrite every 0-sized struct/array
value to StructMake0/ArrayMake0, so unSSA-able operations on zero-sized data never reach expand_calls.

In go1.27.3 two independent paths cover this case; both are reverted:

1. `ssa/copyelim.go` `phielim`: removed the loop-top block
   `if t := v.Type; (t.IsStruct()||t.IsArray()) && t.Size()==0 { v.reset(OpEmpty) }`
   (the go1.27 spelling of the fix's hunk; Make0 ops became OpEmpty). Reverses the fix hunk directly.
2. `ssa/value.go` `CanSSA`: removed the early `if t.Size() == 0 { return true }`. This makes zero-sized
   arrays like `[2]stringer` SSA-able, which is the second line of defence that hides the bug. Without it,
   a zero-sized array with NumElem > 1 is unSSA-able again, as at the time of the fix, so the
   unSSA-able loads/selects on zero-sized data reach expand_calls.

Oracle: `test/fixedbugs/issue65808.go` fails with
`internal compiler error: 'foo.toStrings': value v2 still has 1 uses` (compile of the autogenerated
wrapper for the embedded zero-sized array). TestShouldTest passes.
